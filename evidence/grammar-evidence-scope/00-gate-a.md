# A1 语法证据登记口径 —— 验收材料

日期：2026-08-10 · 分支 `codex/m2-stable-roles` · 设计：`docs/PROJECT.md` §12.5（新增 §11.11）

## 1. A1 的原始理由（「证据饿死」）已经不成立

原提案是「口径从『用户问的那个点』扩到『回答覆盖到的点』，治 §11.9 的证据饿死（29 次提问 0 条）」。查真实库后发现**那个饿死是模板 bug 造成的，2026-08-09 已经修好**，当前口径的实际产出是：

```
 msg |   lens    |                 问题                  | 登记数
  70 | meaning   | 「きれい」在这里是什么意思？          |      0   ← 正确，词义问题
  72 | structure | 「きれい」在这句里的语法结构…         |      2
  74 | chinese   | 「きれい」和中文的说法有什么不同？    |      0   ← 正确
  76 | chinese   | 「チャンネル」和中文的说法…          |      0   ← 正确，词汇
  82 | structure | 「わたしは 学生です」在这句里的语法…  |      2
```

`structure` 角度稳定出 2 个点；另外三次出 0 是**正确的**（§12.5：查词不登记语法）。

**所以 A1 打的位置换了。** 两处真实缺口：

**① 陪读侧的口径已经和入口不符（不是产出不足，是描述失效）。** 原文写「只标注使用者在本轮**明确询问**的语法点」，但 §5.15 用可点的角度取代预填模板之后，使用者点「结构」时**根本不点名任何语法点**——按字面执行这条在角度流程下无从落地。

**② 纠错侧有真实漏标。** 语法类 5 条里挂上 3 条，其中一条能确诊：

```
 「ないですが」→「お肉は入っていませんが」，理由讲的是て形+いる的否定，
 而目录里 verb-te-iru 是存在的 —— 该挂却没挂。
```

而 naturalness(5) / word_choice(3) / register(1) 共 9 条全部为 0，这是**正确的**（§12.5 明写留空）。

## 2. 改了什么

| 侧 | 内容 |
|---|---|
| 陪读 | 口径改为「本轮回答**实质讲解过**、且属于使用者所问那句话的点」。**四条硬边界一字未动**：只是被动出现的不登记、主动扩展到别处的不登记、问的是词义句意的不登记、没把握的不登记。`COMPANION_PROMPT_VERSION` → `companion-turn-v2` |
| 陪读 | 新增一条守卫：目录里没有精确对应时不要退而选最接近的那个（**实测只有 1/3 生效，见第 4 节**） |
| 纠错 | `category=grammar` 时加一步可操作检查：先看 replacement 实际用到的形式在不在目录里。**不降低门槛**——word_choice / naturalness / register / 没把握仍然留空。`CHAT_PROMPT_VERSION` → `chat-turn-v2` |

**为什么这不越 §13.2 的线**：写入路径只调用 `mark_grammar_encounter(status='encountered')`，而自动证据按 §5.10 不得降级手动状态。所以放宽后**登记的仍然只是「已撞见」，永远不会变成「已弄懂」**，「被动看到不等于理解」的边界没有被动。

## 3. 真实模型验证（连百炼 `qwen3.7-max`，独立库）

按上一轮（C1）的教训，真实验证用**专用库 `harvest_a1_live` / `harvest_a1_live2`**，不与测试套件共用。

**陪读侧密度提高了，新增的点都是真讲过的：**

```
 「毎日日本語を勉強しています」  结构 → 3 个：particle-wo, verb-masu, verb-te-iru
 「友達に本を貸してもらいました」结构 → 3 个：particle-ni-place, verb-te, giving-receiving
```

对比历史基线的 2 个/次，现在是 **2–3 个/次**。

**纠错侧这次没能验证到。** 重跑「ないですが」时模型把它归成了 `word_choice` 而不是 `grammar`，新增的检查只在 `category=grammar` 时触发，所以 `grammar_key` 仍为 null——**而按 §12.5，word_choice 留空是正确行为**。也就是说那条漏标有一部分是**分类**问题，不只是标注问题。这一条**未被证实修好**，如实记下。

## 4. 一个必须如实说的负面结果

**放宽口径引入了一类新的错标，而提示词治不了。**

「友達に本を貸してもらいました」里的 に 是 てもらう 的**动作来源**，而目录里 に 只有 `particle-ni-time`（时间）和 `particle-ni-place`（存在・到达），两条都不是它。模型挑了最近的一个。

我加了一条明确守卫，**连这个例子本身都写进了提示词**，然后跑三次同一句：

```
 msg | 登记数 | keys
   3 |      3 | giving-receiving, particle-ni-place, particle-wo   ← 仍错标
   5 |      3 | giving-receiving, particle-ni-place, particle-wo   ← 仍错标
   7 |      2 | giving-receiving, particle-wo                      ← 正确省略
```

**2/3 仍然错标，约 1/3 生效。** 根因是**目录缺项**，不是模型不听话——它正确讲解了「友達に」，需要一个 key，而目录里没有。放宽之前它标的点少，这个缺口没暴露。

**为什么带着已知错标上线**：`POST /grammar/evidence/{event_id}/reject` 已经存在（§12.5），错标可由使用者撤销，且撤销作为新事实保留、不是编辑历史。**这是前提，不是借口。**

**为什么不现在补目录**：补一行 `particle-ni-agent` 不需要迁移（§12.2），但触发它的是**我为验证造的句子，不是使用者真实撞见的内容**。§12 的原则是「按你实际撞见的内容组织」；一旦开始按模型「想标什么」补目录，就会滑向按教材补全，那正是 §12.1 要防的。已记入 §11.11，等真实撞见并撤销过一次再补。

## 6. 偏离说明

1. **A1 的目标位置与原提案不同**，理由见第 1 节：原提案的前提（证据饿死）已被 2026-08-09 的模板修复解决。
2. **纠错侧的改动未被真实验证证实有效**（第 3 节）：重跑时模型改了分类，检查没触发。
3. **陪读侧引入了一类已知错标，且守卫只有 1/3 生效**（第 4 节），依赖既有撤销路径，并已把目录缺项记入 §11.11。
