# HLS 下载包的本机预览(§15.10)

## 它要解决的实况

使用者的原话:「刚才我传了文件夹内容,目前的情况是**无法播放**,所以我也没办法切分。」

上传、解压、切分、封面在 2026-08-11 全部已经跑通,唯独拆分页放不出画面。而 §15 整套东西的前提就是**边看边打点**——看不见就没法切,后面全断。

## 根因

**`AVPlayer` 不接受 `file://` 上的 HLS 播放列表。**

包本身没有任何问题:ffmpeg 读得很顺(切分与取帧都成功),`AVAssetDownloadURLSession` 产出的 `.movpkg` 也照播。是 AVFoundation 对 HLS 只走 HTTP。

这条结论**写在本项目自己的 `HLSAssetDownloader.swift` 注释里**。在读到它之前我连着三次靠猜去改:

1. 把文件夹拷进 App 容器(以为是安全作用域);
2. 把播放列表改名成 `index.m3u8`(以为是扩展名识别);
3. 给无后缀分片统一加 `.ts` 并重写列表(同上)。

三次都没中。前两步是必要的(见下),但都不是原因。**教训:症状在客户端时,先去读自己已有的那段代码,再动手。**

## 做法与它的边界

`LocalMediaServer`:`NWListener` 起在 `127.0.0.1:<系统分配>`,把**一个目录**喂给 `AVPlayer`,支持 Range(一拖进度条就会来 Range 请求,不是可选项)。

这是在自己进程里开了一个可被访问的口子,所以范围刻意收窄:

- **只绑回环**(`requiredLocalEndpoint = .hostPort(host: .ipv4(.loopback), …)`),同一 Wi-Fi 上的任何人都到不了;
- **端口由系统分配**,不写死;
- **只服务那一个目录**:路径 resolve 之后必须落在 root 内,`..` 与绝对路径都拒绝,目录本身也不列出。不是「把沙盒挂到 HTTP 上」;
- 只接受 `GET` / `HEAD`。

生命周期三层:离开页面 `teardown()` → `deinit` 兜底 → 进程死亡是绝对下限。`scenePhase` 回到 `.active` 时重启(回环监听在后台会被系统收掉)。

**实测这一条**:

```
=== 拆分页打开时 ===
Harvest 50663 ... TCP 127.0.0.1:52936 (LISTEN)

=== 离开拆分页后 ===
(空)
```

一个监听、回环、随机端口;退出即消失。

## 顺带修的交互缺陷(只有上手才会发现)

时间轴原来**只能点,不能拖**。而 0:00 时播放头正落在系统返回手势的热区里,于是「按住播放头往右拖」这个最自然的动作**把整个页面划走了,切点一起丢掉**——实测复现,一次就把页面弹回素材库。

改成时间轴自己用一个 `DragGesture(minimumDistance: 0)` 同时接管点与拖:既能拖着找准位置(这本来就是「精度全靠打点」该有的手感,§15.8),也把这个触摸从返回手势那里抢了回来。

## 实测(模拟器,两种真实形态各走一遍)

fixture 都放进模拟器的「我的 iPhone」(`group.com.apple.FileProvider.LocalStorage`),按使用者截图里的形状命名(`play` + `TZhO-#####`)。

| 形态 | 结果 |
|---|---|
| 无后缀列表 + `.ts` 分片(ffmpeg 直出,7s) | 读到时长 0:07、**画面渲出**、`>>` 可跳、标题为文件夹名 |
| **列表与分片全无后缀**(ffmpeg 直出,30s) | 读到 0:30、画面渲出、**从最左边起拖 → 走到 0:10、页面没被划走 → 「在这里切一刀」亮起 → 切出 2 节(0:00–0:10、0:10–0:30)** |

第二行是最难的形态,也是使用者手上那种。

## 两个把我自己绕进去的坑,记下来

**1. 第一版 fixture 拿错了包。** 我用了 `hls-a`(78KB/6s)——那是之前测 `extract_audio` 留下的**纯音频**包。看到 AVKit 画出 QuickTime 占位图、时间在走但没有画面,我一度以为渲染坏了并去怀疑模拟器。**占位图对纯音频资源恰恰是正确表现。** 换 `hls-v`(330KB/6s)后画面正常。判据很简单:6 秒 78KB 不可能有视频。

**2. 模拟器截图抓不到视频层。** 同一个屏幕,`simctl io screenshot` 给的是黑的——mp4 也一样黑,所以这不是 HLS 的问题。要用 `simctl io recordVideo` 录下来再取帧(`qlmanage -t`)才看得见画面。暂停之后截图能拿到画面,播放中拿不到。

**一个不该顺着追的方向**:我曾用「同一个分片重复 10 次 + `EXT-X-DISCONTINUITY`」拼出一个 60 秒的长 fixture,结果时长正确、首帧正常但**跳转不动**。那是 fixture 的毛病(10 个分片时间戳完全相同),不是代码的毛病;换成 ffmpeg 直出的 30 秒包后跳转正常。**合成的测试数据出问题时,先怀疑数据。**
