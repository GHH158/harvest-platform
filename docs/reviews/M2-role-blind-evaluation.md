# M2 稳定角色首轮真实模型盲测审计

日期：2026-08-09<br>
分支：`codex/m2-stable-roles`<br>
被测版本：`role-manifest-v1` / `role-perspective-v1`<br>
模型路由：DashScope / `qwen3.7-max`（本机未配置 DeepSeek）

## 结论

**本轮不通过，而且不能计为一次有效盲测。M2 继续保持进行中，不得进入 M3 圆桌。**

这不是因为角色名字或语气不够鲜明，而是更基础的两层契约没有成立：三位参与者没有稳定交付各自视角的增量；验收脚本也没有保证 trace、匿名结果和答案键彼此完整且隔离。继续给角色增加人设故事不会修复这两个问题。

## 实际执行

固定题集为 `backend/tests/fixtures/role_regression_cases.json` 的 10 题，每题按 A/B/C 调用葵、圭、林三位参与者，共尝试 30 个单角色 preview。运行最终打印：

```text
{"completed_calls": 28, "failed_calls": 2}
```

preview 本身没有写学习事实、学习者记忆或聊天消息，仍守住 M2 的副作用边界。

但运行开始后发现当前 `DATABASE_URL` 指向的库没有 `decision_trace` 表。`_record_decision_trace()` 按既定退化原则吞掉异常，所以模型回答继续生成，而 30 次 trace 写入全部失败。控制台异常又在 SQL 参数中暴露 `subject_key=<role_id>`，紧邻匿名候选输出；因此评审者已经可能看到候选与角色的对应关系，无法再诚实地计算去署名辨认率。

此外，脚本只向控制台打印结果，没有先写私有匿名文件。首个大输出块被终端截断，导致两次结构化失败无法从持久化证据准确定位到题目和候选。事后补写角色映射或凭记忆重建结果都不构成有效验收。

## 去署名输出观察

虽然协议已失效，可见片段仍足以定位产品问题：

| 观察项 | 可见结果 | 判断 |
|---|---|---|
| 角色主视角 | 可观察成功结果反复返回 `focus_tags=["naturalness"]` | 圭的语法结构、林的中文迁移没有在结构化结果中稳定生效 |
| 同题增量 | 过去时、`ておく`、`流会`、已经自然的天气句、对部长的语体、餐厅点餐省略等题中，三个答案大多只是换措辞复述同一完整答案 | 冗余度过高，尚不能证明多视角值得展示给用户 |
| 不强行纠错 | 三位候选都判断「今日は風が強いです」无需修改 | 这一条通过，但三份解释仍高度重复 |
| 场景诚实度 | “和同事聊”没有说明上下级或亲疏，候选却分别断言应使用简体或敬体 | 缺证据时仍会擅自补齐关系，形成无学习价值的冲突 |
| 过度精确 | 对「近所」给出固定“步行 5–10 分钟”等未经题目支持的范围 | 角色表现压过证据边界，应改为语境相关判断 |
| 契约可靠性 | 30 次中只有 28 次得到可读结构 | 不满足稳定预览的最低可靠性要求 |

盲评前不揭示角色映射的规则已经被控制台日志破坏，所以本报告不提供“预测角色”和“真实角色”的伪分数。

## 根因

1. `role-perspective-v1` 的精确 JSON 示例把 `focus_tags` 固定写成 `naturalness`。对真实模型而言，示例比前面的抽象人设更像必须模仿的输出锚点。
2. 三位参与者都收到“独立判断当前问题”的任务，却没有明确收到“只交付本视角增量卡片”的协议。模型为了保证服务质量，会自然地各自生成一份完整标准答案。
3. “没有增量就简短说明”只是软提示；契约没有校验输出是否至少包含本角色的主视角标签。
4. 临时验收命令绕过了应用 lifespan 的 `apply_schema()`，外部调用前也没有查询 `decision_trace` 做硬前置检查。
5. 匿名候选、答案键和 trace 摘要没有分别持久化，导致终端截断和日志泄露都能使整轮作废。

## 已实施的修正

- 提示词升级为 `role-perspective-v2`，响应 JSON 结构保持兼容。
- 每位参与者新增明确的分析顺序、主视角标签与退出条件：葵只交付自然度/语体增量，圭只交付语法结构增量，林只在存在具体中文迁移时交付迁移增量。
- JSON 示例按角色使用各自的主标签，服务端校验至少命中一个本角色主标签；不匹配时只允许一次结构修复，仍不匹配则以 `role_alignment` 失败。
- 新增开发命令 `backend/scripts/run_role_blind_evaluation.py`：没有显式的 30 次外部调用确认参数就拒绝运行；通过真实应用 lifespan 先应用 schema，并在第一笔付费调用前确认 trace 可查询。
- 新命令使用新的 `m2-blind-v2` 种子；匿名评审表和答案键写入两个权限为 `0600` 的私有文件，逐次持久化。控制台只显示 case 序号与 A/B/C，不显示角色。
- 每轮结束核对恰好 30 条新 trace、每位角色各 10 条，以及 prompt 版本；任一不满足即标记该轮不可用于盲评。

复验命令（必须先取得新的 30 次调用授权）：

```bash
PYTHONPATH=backend .venv/bin/python -m scripts.run_role_blind_evaluation \
  --confirm-30-external-calls
```

不带确认参数时命令在进入应用 lifespan 和模型调用前返回失败；默认产物写在 Git 忽略的 `backend/data/role-evaluations/`。

## 下一轮通过门槛

下一轮仍使用相同 10 题、共 30 次 preview，但必须重新取得外部调用授权。通过需要同时满足：

1. 30/30 请求产生可读结构，且 30/30 新 trace 完整、prompt 全为 `role-perspective-v2`；
2. 30/30 输出至少包含本角色主视角标签；
3. 在不查看答案键的前提下，30 个候选的角色辨认率至少 80%，且任一角色不低于 70%；
4. 10 组中最多 3 组可以被评为“基本只是换措辞重复”；
5. 日语核心事实零严重冲突，不通过虚构人格制造分歧；
6. 已经自然的句子不被强行纠错，证据不足的关系、地域、时代和固定范围明确标为推断/不确定；
7. 先保存去署名评审，再打开答案键并计算结果。

在这些条件同时通过前，M2 的路线图复选框继续保持未完成，M3 不开始。
